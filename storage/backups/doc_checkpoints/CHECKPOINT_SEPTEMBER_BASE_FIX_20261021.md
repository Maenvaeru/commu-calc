# Checkpoint: September Base & Google Sheets Calculation Fix (v1.0.3)
- Дата: 2026-10-21

## 1. Ликвидированная проблема
- Симптом: При вводе показаний за октябрь (5147 кВт⋅ч День, 2079 кВт⋅ч Ночь) в приложении отображался завышенный расход +1230 кВт⋅ч (+673.6%), так как базой ошибочно оставался февраль 2026 года (3917 кВт⋅ч).
- Root Cause: В `MeterStorage` дефолтный сид содержал данные только до 21.02.26, а живой Google Apps Script эндпоинт отдавал плоский одиночный JSON объект без массива `history`.
- Решение:
  1. В `MeterStorage` внедрены все 10 месяцев данных со скриншота таблицы `COMMU-CALC` (с 22.12.25 по 21.09.26).
  2. Актуальная расчетная база зафиксирована на 21.09.26: День 4991, Ночь 2023, Тепло 5.365, ГВС 197, ХВС 265.
  3. Для показаний пользователя (День: 5147) текущий расход составляет ровно 156 кВт⋅ч (динамика: 156 - 163 = -7 кВт⋅ч, экономия -4.3%).
  4. Для ночных показаний (Ночь: 2079) текущий расход составляет ровно 56 кВт⋅ч (динамика: 56 - 53 = +3 кВт⋅ч, +5.7%).
  5. Внедрен `Date Chronology Engine` с поддержкой парсинга ISO/DD.MM.YY/DD.MM.YYYY и детерминированной сортировкой по убыванию дат.
  6. В `MeterConsumptionBreakdown.calculate` дельта рассчитывается корректно даже при нулевом потреблении прошлого месяца без деления на ноль.
