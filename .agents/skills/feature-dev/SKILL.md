# 🚀 Feature Development (7-Phase Workflow)

Структурированный сквозной цикл проектирования и реализации новых функциональных возможностей без хаотичного кодинга.
Основано на официальном стандарте Anthropic `feature-dev`.

## Философия
Код пишется только тогда, когда понятна архитектурная ниша, устранены двусмысленности требований и согласован пошаговый план.

## 7 фаз реализации

```
1. Discovery ──> 2. Exploration ──> 3. Questions ──> 4. Design ──> 5. Gate (99%) ──> 6. Implementation ──> 7. Review
```

### Фаза 1: Discovery (Понимание задачи)
- Сформулируй проблему пользователя и ожидаемую ценность.
- Определи ограничения системы, производительности и окружения.

### Фаза 2: Codebase Exploration (Исследование кодовой базы)
- Найди аналогичные фичи и существующие абстракции в проекте.
- Проследи сквозной поток вызовов (UI -> Controller/Router -> Service -> Storage).
- Составь список файлов для понимания с номерами ключевых строк (`file:line`).

### Фаза 3: Clarifying Questions (Снятие двусмысленностей)
- Выяви граничные случаи (пустые данные, потеря сети, гонки).
- Уточни поведение при сбоях (graceful degradation, fallback, ретраи).

### Фаза 4: Architecture & Interface Design (Проектирование)
- Спроектируй сигнатуры API, схемы данных и компонентную структуру.
- Следуй соглашениям проекта (конвенции над конфигурацией). Не создавай лишних фабрик и адаптеров.

### Фаза 5: Plan Approval Gate (99% остановка)
- Представь лаконичный пошаговый план реализации.
- **ОСТАНОВИСЬ.** Запроси подтверждение человека («Одобрить» / «Приступай»). До получения одобрения запрещено вносить правки в код.

### Фаза 6: Implementation (Чистая монолитная реализация)
- Внедряй изменения минимальными диффами.
- Сохраняй целостность существующих тестов и интерфейсов.

### Фаза 7: Quality Review & Hardening
- Проверь обработку ошибок, отсутствие утечек ресурсов и блокировок.
- Убедись в соблюдении линтинга и инвариантов проекта.
