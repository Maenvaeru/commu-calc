# 💾 Project Checkpoint & State Capture (Королевское сохранение)

Стандарт фиксации успехов разработки, сохранения контекста сессии и создания чекпойнтов документации.
Основано на официальных практиках Anthropic `project-artifact` и `claude-md-improver`.

## Главный закон
Чекпойнт — это не просто пустая галочка. Это независимый артефакт, прочитав который любой агент или разработчик мгновенно поймет текущее состояние, ключевые решения, архитектурные инварианты и сможет продолжить работу без потери контекста.

## Структура королевского чекпойнта (CHECKPOINT_*.md)

Каждый чекпойнт создается в папке `storage/backups/doc_checkpoints/CHECKPOINT_<TOPIC>_<YYYYMMDD>.md` и содержит:

1. **Шапка статуса:**
   - Дата и время создания.
   - Версия системы / тулбара / релизный тег.
   - Статус DevLog: количество правил, инцидентов, размер Hot Tier.
2. **Ликвидированные проблемы и решенные задачи:**
   - Точные симптомы сбоя.
   - Корневая причина (Root Cause).
   - Инженерное решение (с ссылками на `file:line`).
3. **Архитектурные изменения и реестр файлов:**
   - Таблица измененных, созданных и удаленных файлов.
   - Ключевые diff-фрагменты и обновленные контракты API.
4. **Матрица верификации (QA Proof):**
   - Результаты тестов, прогонов синтаксиса (`node --check`, lint, unit-тесты).
   - Статус живых окон / процессов / портов.
5. **Новые инварианты для Development.md:**
   - Сформулированные телеграфные правила для предотвращения повторных ошибок.
   - Ротация в архив при превышении лимита Hot Tier (<35 КБ).

## Чеклист выполнения чекпойнта
1. [ ] Проверить целостность синтаксиса измененного кода.
2. [ ] Сформировать `CHECKPOINT_<NAME>_<DATE>.md` в `storage/backups/doc_checkpoints/`.
3. [ ] Синхронизировать статус в `Development.md` через `tools/devlog-engine.js`.
4. [ ] Вывести лаконичный отчет с подтверждением успешного сохранения.
