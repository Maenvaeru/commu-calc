# 🔍 Code Review & Integrity (Ревизия целостности кода)

Систематический аудит кодовой базы на соблюдение архитектурных инвариантов, совместимость контрактов и отсутствие регрессий.
Основано на официальном стандарте Anthropic `code-review` и `pr-review-toolkit`.

## Ключевой принцип
Ревью кода — это не вкусовщина и не спор о форматировании. Задача ревьюера — с математической строгостью доказать отсутствие деградации API, утечек ресурсов, рассинхрона типов и скрытых регрессий.

## Направления проверки (Review Dimensions)

### 1. Архитектурная целостность и KISS (DHH Monolith)
- Проверка на лишние абстракции: не внедрены ли паразитные фабрики, адаптеры и слои с единственной реализацией.
- Соблюдение принципа DRY: устранено ли дублирование бизнес-логики и нормализации данных.
- Чистота границ: отсутствие циклических зависимостей между модулями.

### 2. Совместимость API и стабильность контрактов
- Обратная совместимость сигнатур функций, аргументов и структур возврата.
- Соответствие форматов сериализации (JSON, IPC, CDP events).
- Защита от breaking changes для внешних потребителей.

### 3. Целостность типов и граничные условия (Edge Cases)
- Поведение при `null`, `undefined`, пустых строках и пустых коллекциях.
- Переполнение числовых значений, деление на ноль, некорректные даты.
- Корректная обработка Unicode, длинных путей и спецсимволов.

### 4. Производительность и ресурсы
- Отсутствие утечек памяти: отписка от слушателей событий (`removeEventListener`), очистка интервалов (`clearInterval`).
- Защита от OOM: ограничение размеров очередей, буферов и истории.
- Исключение N+1 запросов и блокировок Event Loop на главном потоке.

## Процесс ревью
1. **Scope Diff:** Определение минимального набора измененных файлов (`git diff`).
2. **Invariants Check:** Сверка с журналом `Development.md` — не нарушаются ли зафиксированные инварианты.
3. **Verdict:** Четкая фиксация замечаний с указанием `file:line`, описанием риска и конкретным предложением по исправлению.
