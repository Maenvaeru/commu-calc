# DevLog Compactor & Engine — Стандарт инвариантов и умного поиска разработки (2026)

Навык дистилляции, ведения и семантически-ранжированного поиска по журналу ошибок `Development.md` и архиву `Development.archive.md`.
Предотвращает разрастание контекста (>35 КБ), галлюцинации номеров инцидентов и повторение пройденных граблей.

---

## 1. Архитектурный принцип: Hot Tier vs Cold Tier

1. **Hot Active Tier (`Development.md`)**:
   - Размер: не более 15–32 КБ (<3500 токенов).
   - Раздел 1: `## Ошибочные шаги и грабли (Banned Antipatterns)` — сквозные запреты 1..N.
   - Раздел 2: `## Зафиксированные инциденты и решения` — хроника инцидентов 1..M.
   - Всегда загружается моделью перед задачей.

2. **Cold Archive Tier (`Development.archive.md`)**:
   - Размер: не ограничен.
   - Содержит вытесненную историю старых инцидентов и детальные дампы.
   - Модель НЕ читает архив целиком. Доступ осуществляется мгновенно через гибридный поиск:
     `node tools/devlog-engine.js search "<запрос>"`

---

## 2. Современный CLI: `tools/devlog-engine.js`

Все операции с журналом автоматизированы и исключают ручные ошибки нумерации:

### 1. Проверка статуса и счетчиков:
```bash
node tools/devlog-engine.js status [path]
```
Выдает точное число правил, инцидентов, размер в КБ и явный номер для следующей записи (`след: #ID`).

### 2. Умный гибридный поиск (BM25 + TF-IDF) по Hot + Cold архивам:
```bash
node tools/devlog-engine.js search "Wan2.1 VAE 12ch" [path]
node tools/devlog-engine.js search "Krea2 FlowShift" [path]
```
Мгновенно находит релевантные инциденты и правила за 20 мс по всей базе проекта без расхода токенов контекста.

### 3. Автоматическое добавление инцидента (Auto-Increment & Atomic):
```bash
node tools/devlog-engine.js add --incident "Заголовок проблемы" --cause "Причина" --fix "Решение" [path]
```
- Детерминированно берет `Max(ID) + 1` с диска.
- Исключает галлюцинации номеров.
- Атомарная запись через `.tmp` файл.

### 4. Автоматическое добавление архитектурного правила:
```bash
node tools/devlog-engine.js add-rule --title "Заголовок" --trap "Ловушка" --rule "Запрет/Решение" [path]
```

### 5. Сжатие и ротация в архив:
```bash
node tools/devlog-engine.js compact [path] --keep 10
```

---

## 3. Золотой стандарт телеграфного инварианта

Каждая запись в `Development.md` обязана формулироваться строго по формуле:

```markdown
N. **[Подсистема / Метод]:** Ловушка/Симптом (Trap). Корневая причина (Root Cause). -> Запрет/Обязательное решение (Enforced Rule).
```

### Категорически запрещено:
- Галлюцинировать номера инцидентов (всегда сверяться с системным бейджем `след: #ID` или вызывать `devlog-engine status`).
- Нарративная вода («Мы долго пытались понять», «Как оказалось»).
- Промежуточные неверные гипотезы (фиксируется только доказанный факт).
- Сырые дампы логов и стектрейсы длиннее 2 строк (переносить в `Development.archive.md`).
