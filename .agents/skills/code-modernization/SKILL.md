# 🏗️ Code Modernization & Architecture Uplift

Систематическая модернизация и рефакторинг кодовой базы с математическим доказательством сохранения или улучшения поведения.
Основано на официальном стандарте Anthropic `code-modernization` и методике Clean Monolith.

## Ключевой принцип
Модернизация без верификации — это внедрение скрытых регрессий. Код считается модернизированным только тогда, когда независимый тест или сравнительный прогон доказывает эквивалентность поведения.

## 8-фазный цикл модернизации

```
0. Intent ──> 1. Preflight ──> 2. Assess ──> 3. Map ──> 4. Extract Rules ──> 5. Brief (Gate) ──> 6. Uplift/Transform ──> 7. Verify Proof
```

### Фаза 0: Intent & Scope
1. Определи цель модернизации:
   - **Uplift**: Обновление версии того же стека (Node 18 -> 22, Electron, React).
   - **Transform**: Модульная замена устаревших библиотек/подсистем на чистые монолитные решения.
   - **Reimagine**: Перепроектирование архитектуры с нуля по спецификации бизнес-правил.
2. Зафиксируй границы: какие папки/модули трогаем, какие строго read-only.

### Фаза 1: Preflight & Environment
1. Проверь окружение: собирается ли текущий проект, проходят ли существующие тесты.
2. Проверь наличие бэкапа или Git-коммита перед началом любых правок.

### Фаза 2: Assess (Инвентаризация и сложность)
1. Составь инвентарь модулей, зависимостей, точек входа и цикломатической сложности.
2. Выяви технический долг, устаревшие API и потенциальные узкие места.

### Фаза 3: Map (Карта зависимостей и данных)
1. Построй граф потоков данных: Entry Points -> Services -> Storage/API.
2. Выяви циклические зависимости и паразитные связности между модулями.

### Фаза 4: Extract Rules (Бизнес-правила Given/When/Then)
1. Выдели критические бизнес-инварианты в формате:
   - `Given`: Начальное состояние и контекст
   - `When`: Пользовательское действие или вызов API
   - `Then`: Точный ожидаемый результат и сайд-эффекты
2. Каждое правило P0 обязано иметь привязку к строкам исходного кода (`file:line`).

### Фаза 5: Modernization Brief & Approval Gate (99%)
1. Сформируй итоговый бриф: объем изменений, порядок модулей, стратегия отката.
2. **ОСТАНОВИСЬ.** Запроси подтверждение человека («Одобрить» / «Приступай»). Никакой код не переписывается до одобрения.

### Фаза 6: Uplift & Transform (Исполнение)
1. Применяй минимально достаточные, идиоматичные изменения без оверинжиниринга.
2. Устраняй дублирование и лишние прослойки по принципу DRY и KISS.

### Фаза 7: Verify Proof (Доказательство эквивалентности)
1. **Canary Test**: Намеренно сломай одну строчку — тесты ОБЯЗАНЫ упасть (проверка чувствительности тестов).
2. **Side-by-side run**: Прогон старых и новых модулей на одинаковых граничных данных.
3. Проверка нештатных входов: пустые значения, переполнение, невалидный JSON, таймауты.
